Weekly certificates have a publication switch in the teacher award form and history. New certificates default to private. Only the existing verified weekly-certificate teachers (Sister Saba and Ustadh Mehran) may publish or hide them, including certificates previously saved by either teacher.

Private certificates are available for authorized teacher preview/download, but not in parent/student portals or direct family certificate links. Publishing creates a 150-point total Qabila bonus and family notification, and attempts the recognition email. Mumin credits the awarded student; Mum shares the total across her linked children with assigned Qabilas. Repeating a publish request does not duplicate credits or notifications. Hiding withdraws all the certificate's shares and removes portal notifications. Publishing again restores the bonus and announces the publication again. Already delivered emails cannot be recalled. Publication is manual; there is no automatic two-day release.

The `20261031120000_certificate_publication` migration adds the Mum certificate's original point recipient and, as requested, hides existing weekly certificates, removes their notifications and withdraws only their certificate Qabila credits. Certificate records and unrelated badges/points remain intact. `npm start` now runs `prisma migrate deploy` before starting the app, so the privacy migration is applied during the normal startup. The existing `npm run start:migrate` command also supports this. A hosting command that calls `next start` directly must apply migrations first. The migration cannot be verified against production from a local checkout without a live database connection.

Weekly certificates are excluded from collectible badge galleries and badge download links. An old weekly `/badges/code` URL redirects to the certificate. No additional badge record is created for either type of weekly certificate.

To release a certificate later, open the Mumin or Mum weekly certificate tab, find its entry in the history, check **Public**, and click **Save visibility**. To hide a published certificate, uncheck **Public** and save. The **Hide all weekly certificates** control is also available for later use and requires explicit confirmation.

The `20261102100000_restore_weekly_certificate_credits` migration restores missing 150-point credits for published, non-revoked Mum/Mumin of the Week certificates with assigned Qabilas, preserving the original award dates. It does not publish drafts, send emails, create badges or duplicate existing certificate credits. Its original single-child Mum allocation is superseded by the sharing migration below. Publication fails explicitly if no eligible recipient has a Qabila, and credit descriptions are limited to the ledger column length. Re-saving an already-public certificate repairs/rebalances its credit without sending another announcement.

The `20261103100000_share_mum_certificate_points` migration redistributes existing published Mum of the Week credits equally per linked child with an assigned Qabila (75 each for two, 50 each for three). Children in the same Qabila contribute their individual shares to the same group total. The total stays 150, not 150 per child or per group. Whole-point remainders are allocated by stable student-ID order (four children receive 38, 38, 37, 37). Unassigned duplicate records cannot absorb a Qabila share; no Qabila is automatically assigned. The migration preserves original award dates and leaves private/revoked awards, other Mum recognitions, Mumin certificates and unrelated points unchanged. Runtime publication uses the same allocation and locks the certificate; hiding withdraws every share, and re-saving a public certificate rebalances it safely. The legacy `pointsStudentId` field is no longer used to select a single Mum beneficiary. The read-only audit now reports expected per-child shares and detects an incorrect distribution even when total credit is 150.

The shared contribution-history dialog has an Activity → Weekly certificates filter. Both Mum and Mumin credits are listed under the credited child's Qabila, with their original award date. The filter applies before pagination, so older certificates can be found without paging through newer homework/quiz activity. Qabila/member totals still include all recorded contributions. It does not fabricate history entries for certificates without ledger credits.

To diagnose a missing live entry, run `node scripts/audit-weekly-certificate-credits.mjs` in the deployed App Platform console. This read-only check reports public/private status, expected versus recorded points, the selected child, linked children and the Qabila actually holding each credit. It does not expose credentials or send messages. Confirm the migration above ran if public credits are missing; saving an already-public certificate's visibility also retries its missing credit. A migration or successful save must be verified against the live database before reporting that a specific award was restored.
