Parents and students now have a dedicated **Homework & Tasks** entry in the main navigation, including mobile quick access. Both pages show programme filters and newest assignments first. Student task links open the exact assignment, including legacy `/student/courses?task=...` links. The curriculum page links to the dedicated homework workspace.

Parents see instructions, resources, deadlines, submission timing and feedback, and can submit an answer, file or both directly from their linked child's task card. The action checks ownership of the selected child, current task visibility and unlocked access. Parent submissions use the same first-submission timing, one-time child Qabila points and teacher notification queue as student submissions. A red navigation indicator counts unread homework alerts for the selected child, excluding deleted tasks, tasks scheduled for the future and modules disabled for student handover. The indicator remains until review or successful submission; generic notification clearing does not dismiss it. Reviewing is distinct from submitting homework.

Students can type an answer, upload a file (including audio), or do both. Existing work/files remain available for updates. The submission action rechecks the student's currently visible assignments and unlocked access before accepting a task. First-submission timing and the existing idempotent 10-point Qabila submission award are retained.

Assignment creation and submission queue notifications atomically using the existing durable `BillingEmailJob` infrastructure, with separate `HOMEWORK_*` statuses. No additional table or migration is required. A production Node worker starts automatically through instrumentation, runs every minute and resumes pending jobs after a deployment. It can be disabled explicitly with `HOMEWORK_NOTIFICATION_WORKER_ENABLED=false`.

Parent and student task emails are sent when the task is live, with the child, programme, week, task and deadline, and a direct Homework link. Every linked parent is included even when the student has a deliverable email. Future launches and disabled handover modules defer notification delivery. The worker rereads task metadata so edited launch dates are respected. Deleting homework cancels its launch job and removes its parent task alerts.

Student submissions queue a teacher notification and email linking to the specific teacher homework card. For newly created tasks the assigning teacher is recorded in the launch job; for older tasks, active programme teachers are filtered by student roster and programme permissions. Superseded submission revisions are discarded. Repeated delivery uses deterministic portal notification IDs and durable email keys. Provider failures, missing configuration and the existing global email quota defer delivery for retry; successful delivery is never assumed from a saved job alone.

Previously created homework is visible in the new pages, but the worker does not send a retrospective launch-email campaign for old assignments. Existing student task URLs redirect to the new workspace.
