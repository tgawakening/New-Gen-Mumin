# Teacher roster achievements and homework

- Teachers receive portal alerts for automatic and teacher-assigned character badges and weekly student certificates. Alerts include a badge thumbnail, student name, reason, and encouragement to celebrate in class.
- Recipient selection follows the same saved/eligible programme rosters and programme scope as the teacher dashboard. Alerts are deduplicated per award; failed deliveries are retried when that recognition is synced again. Past awards can generate their first teacher alert on a later sync; no bulk historical email is sent.
- Badges & Certificates includes roster summaries (including learners without awards), student/type filters, ten students per roster page and ten achievements per history page. Actual badge artwork, downloads and weekly certificate links are available. Revoked/private awards are excluded. Existing certificate-awarding permissions remain enforced.
- Homework launch dates are stored in the existing structured task instructions. No schema migration is required. Legacy tasks without launch metadata remain available.
- Date/time inputs use the teacher profile timezone (Europe/London fallback). Launch defaults to the current local minute and deadline to seven calendar days later; teachers can override either. The saved deadline is exact to the selected minute. Older date-only inputs retain their midnight launch/end-of-day deadline behaviour. Scheduled work is hidden from family coursework and submission is checked server-side. Assignment alerts identify scheduled launch dates; availability updates automatically when the page is opened after launch.
- The assignment popup supports programme/module homework or a specific saved lesson. Lesson-linked tasks inherit the lesson's module and week. The homework overview parses stored task data into readable instructions, named file/resource links, dates and roster submission counts; internal task JSON is never printed. Review links open the matching submission section.
- The first successful submission determines on-time/late status. Updates retain that timestamp and the existing file unless replaced. No deadline means any successful submission is on time. Missing work is explicitly listed for roster students; draft work cannot be reviewed or awarded performance points.
- First submissions are serialized using an enrollment row lock to prevent duplicate records without requiring a schema migration. Performance awards remain separate from the existing submission reward, and are updated rather than added twice.
- New homework submissions earn 10 automatic Qabila points once per student/assignment. Updating work does not grant the reward again. Teacher performance points are an additional, independently editable award. Previously recorded submission rewards are preserved.
- New automatic character badges earn 10 points each. Existing teacher badge values and the 150-point weekly certificate bonus are retained. Character badges and the recipient's Qabila ledger credit now commit in one transaction. Replaying a positive-point award repairs a missing credit without duplicating it or changing historical bonus values; zero-point historical badges are not retroactively repriced.

Validation: focused timing, roster, alert deduplication, submission, award-history access/pagination, homework-review and existing teacher-permission tests. Database operations are isolated with test fixtures; a production MySQL/Google Drive end-to-end submission was not performed locally.
